Give your agents a notebook

The Journal MCP server lets Claude Code, Claude Desktop, Cursor and Codex CLI read, search, create and edit your notes, in the folders you grant.

Set up the server See the fourteen tools

What you need

A Homebase identity
Such as you.dotyou.cloud, signed in to Journal at least once. Join the wait list if you have none.
Node.js 20 or newer
The server runs on your computer through npx. Check with node --version.
An MCP client
Claude Code, Claude Desktop, Cursor, Codex CLI, or any client that can start a local command.

Set it up in four steps

Sign in once on your computer, add the server to your agent, grant it folders, then ask it something to check. It takes about five minutes.

  1. Install the server and sign in

    Pick your agent. In Claude Code the plugin does both in one go. In the others, sign in from a terminal, then add the server to the client's config file.

    Put your own identity in place of you.dotyou.cloud. You sign in once per computer: every client on it shares the same login, kept in your system keychain.

    Paste these into Claude Code, one at a time. The last one opens your browser to approve the server.

    /plugin marketplace add 2002Bishwajeet/journal
/plugin install journal@journal
/journal:login you.dotyou.cloud

    First, sign in from a terminal:

    npx -y https://github.com/2002Bishwajeet/journal/releases/download/mcp-v1.8.1/journal-mcp-1.8.1.tgz login you.dotyou.cloud

    Then open Settings → Developer → Edit Config in Claude Desktop, add this to claude_desktop_config.json, and quit and reopen the app:

    {
  "mcpServers": {
    "journal": {
      "command": "npx",
      "args": ["-y", "https://github.com/2002Bishwajeet/journal/releases/download/mcp-v1.8.1/journal-mcp-1.8.1.tgz"]
    }
  }
}

command = "npx"
args = ["-y", "https://github.com/2002Bishwajeet/journal/releases/download/mcp-v1.8.1/journal-mcp-1.8.1.tgz"]

  2. Approve Journal MCP on your identity

    Signing in opens your Homebase owner console. Approve the app called Journal MCP: it asks for Read + write on your notes drive and nothing else. The terminal then says you're logged in.

    Reload the server so it picks up the login: run /mcp in Claude Code and reconnect journal, quit and reopen Claude Desktop, or restart Cursor or Codex.

    On a computer with no browser, such as over SSH, add --no-browser to the login command. It prints a link to open on any device; approve there, and paste the code Journal shows at the Paste code: prompt.

  3. Grant the folders it may use

    In Journal, open Settings → Agent access and set each folder, or a single note, to None, Read, or Read + write. Everything starts at None, so until you grant something the agent sees no notes at all.

    Mark a note ‘exclude from AI’ and it stays yours alone, whatever its folder allows. The server checks your grants on every tool call, on your own computer.

  4. Check that it works

    Ask your agent to list your Journal folders. It calls list_folders and names each folder you granted, with read or write beside it. Folders left at None don't appear.

    An empty list means the server is connected and nothing is granted yet. An error means the server isn't running: see the fixes below.

If something goes wrong

Not logged in. Run: journal-mcp login <identity>
The server started but found no login on this computer. Run the sign-in step again, then reload the server.
Not a valid Homebase identity
Check the spelling. Give the identity alone, such as you.dotyou.cloud, and make sure it opens in a browser.
Login timed out after 5 minutes
The approval wasn't finished in time. Run the login again and approve Journal MCP in the console it opens.
No browser opens
Over SSH or in a container, add --no-browser and paste the code, as in step two.
Journal MCP needs Node 20 or newer
Install Node.js 20 or later, remove the old one, and restart your client.
The client can't start npx
Desktop apps don't always see your shell's path. Put the full path from which npx in "command".
The agent sees no notes
Nothing is granted yet. Set the folders it needs in Settings → Agent access; the change applies on the next tool call.
Note is read-only for agents
The note's folder is set to Read. Change it to Read + write to let the agent edit.
Revoke access
Remove Journal MCP under Apps in your owner console. To forget the login on one computer, run the login command with logout in place of login you.dotyou.cloud.

Fourteen tools, grouped by job

What each tool does, what it takes and returns, and when an agent should reach for it. Your agent reads the same descriptions when it connects.

Rules every tool follows

Access
A note or folder at None doesn't exist for the agent: it is never listed, and asking for it returns Note not found. At Read, write tools fail with Note is read-only for agents. A note marked ‘exclude from AI’ is never readable or writable.
Merged edits
Every write is applied to the note's current state and merged, so what you type in Journal at the same time is kept. To have an edit refused if the note changed since you read it, pass get_note's modified as expectedModified.
Signed edits
Notes an agent changes are labelled with it, such as agent:claude-code.
Images
In markdown, ![alt](/absolute/path.png) or a base64 data: URI is uploaded into the note. PNG, JPEG or WebP, up to 5 MB each, with EXIF and GPS removed. If one image is invalid, nothing is written. https:// image links stay links.
Note links
[label](journal:note/<id>), or [[Note title]] for the one note you can see with that title.
Layout warnings
When an html or react block sets a width over 390px or uses 100vh, the write still succeeds and the result carries a note saying how to fix it.

Find and read

list_folders

Lists the folders you have granted, each with the agent's access to it.

Use it when
Starting a session, or before create_note, to find a folder's id and whether it is writable.
Try asking
Which of my Journal folders can you see?
Inputs

None.

Returns

A list of { id, name, access }, where access is read or write.

list_notes

Lists granted notes, newest first, optionally from one folder.

Use it when
Browsing what changed lately, or finding a note's id when you know which folder it's in.
Try asking
What did I write in my Work folder this week?
Inputs
folderId string, optional
Only notes in this folder, by its id from list_folders.
limit integer, optional
1 to 200. Default 50.
Returns

A list of { id, title, folderId, modified, tags, access }. No note bodies.

search_notes

Finds granted notes whose title, tags or text contain the query, ignoring case.

Use it when
Looking for a note by a word in it. It matches the exact text, so search one distinctive word rather than a sentence.
Try asking
Find my notes that mention Lisbon.
Inputs
query string, required
The text to look for.
limit integer, optional
At least 1. Default 20.
Returns

The matching notes, in the same shape as list_notes.

get_note

Reads one note, with its body as markdown or as a list of blocks.

Use it when
Before any edit. Ask for blocks before edit_block, and keep modified to pass as expectedModified.
Try asking
Summarise my Trip plan note.
Inputs
id string, required
The note's id.
format "markdown" or "blocks", optional
Default markdown.
Returns

{ id, title, folderId, modified, tags, access } with markdown, or with blocks: a list of { id, type, markdown, attrs }, plus rows of cell markdown for a table. Block ids stay the same while the block exists.

get_authoring_guide

Returns the full reference for writing notes: every block's markdown with examples, how live blocks run, and the design rules that make them match the note in light and dark.

Use it when
Before writing anything beyond plain markdown: tables, callouts, toggles, math, galleries, or a mermaid, svg, html or react live block.
Try asking
Build a chart of my reading log as a live block.
Inputs

None.

Returns

The guide as markdown text, the same as AUTHORING.md.

Write and edit

These need Read + write access. Pick the smallest one that does the job: a passage with replace_in_note, a block or table cell with edit_block, the whole note with update_note.

create_note

Creates a note from markdown in a folder the agent can write in.

Use it when
The note doesn't exist yet. To change one that does, use update_note rather than a second note.
Try asking
Create a note called Standup in my Work folder with today's summary.
Inputs
title string, required
The note's title.
markdown string, required
The body. Images and live blocks allowed.
folderId string, required
A folder with Read + write, from list_folders.
tags string[], optional
Tags for the note.
Returns

{ id, title, folderId } of the new note.

append_to_note

Adds markdown to the end of a note and leaves the rest as it was.

Use it when
Adding to a log, a diary or a running list.
Try asking
Append today's standup summary to my Work log.
Inputs
id string, required
The note's id.
markdown string, required
What to add.
Returns

{ id }.

replace_in_note

Replaces one passage of a note's markdown, exactly as get_note returned it.

Use it when
Changing a word, a date or a sentence. If old_text appears zero times or more than once, the tool says so and nothing changes: retry with more of the text around it.
Try asking
In my Trip plan note, change the flight time from 9:40 to 10:15.
Inputs
id string, required
The note's id.
old_text string, required
Text that occurs exactly once in the note.
new_text string, required
The markdown to put in its place.
Returns

{ id }.

update_note

Rewrites a note's whole body, its title, its tags, or any of them. Blocks kept exactly as get_note returned them stay untouched, links and images included.

Use it when
Restructuring a note, renaming it or retagging it.
Try asking
Redesign my Trip plan note as a day-by-day itinerary.
Inputs
id string, required
The note's id.
markdown string, optional
The new body.
title string, optional
The new title.
tags string[], optional
Replaces all of the note's tags.
expectedModified string, optional
Refuse the edit if the note changed since this time.

Give at least one of markdown, title or tags.

Returns

{ id }.

edit_block

Changes one block of a note by its id: replace it, add a block before or after it, delete it, or change one table cell, row, column or setting. Every other block stays as it is.

Use it when
Editing inside a table, ticking a task, or changing a callout or live block, after get_note with format: "blocks".
Try asking
In my Trip plan table, set Tuesday's plan to Hike.
Inputs
note_id string, required
The note's id.
block_id string, required
The block's id from get_note.
op object, required
One of:
  • replace, insert_before, insert_after with markdown
  • set_text with markdown: a callout's or toggle's body
  • delete
  • set_attrs with attrs: variant, summary, level, language, id, wide or checked
  • set_cell with row, col, markdown
  • insert_row with at and optional cells
  • delete_row, insert_column, delete_column with at
expectedModified string, optional
Refuse the edit if the note changed since this time.
Returns

{ id, block_ids }: the ids of the blocks the edit leaves.

Covers

set_note_cover

Sets a note's cover image, or the cover it shows in dark mode. A public note's link preview uses the cover too.

Use it when
A note needs a picture at the top. Use this rather than an image in the body. Crop to about 1.9:1 first, ideally 2400×1260 and at least 1200×630: the image is uploaded as it is.
Try asking
Use ~/Pictures/lisbon.jpg as the cover of my Trip plan note.
Inputs
id string, required
The note's id.
image string, required
An absolute path on this computer (preferred) or a base64 data: URI. PNG, JPEG or WebP, up to 5 MB.
positionY number, optional
The focal point from 0 (top) to 100 (bottom). Default 50.
dark boolean, optional
Set the dark-mode cover. The note must have a cover already.
Returns

{ id, variant, src, positionY }, with a note when the image is too small or the wrong shape.

clear_note_cover

Removes a note's cover and its dark-mode cover, or only the dark one.

Use it when
A note should go back to having no cover.
Try asking
Take the cover off my Trip plan note.
Inputs
id string, required
The note's id.
dark boolean, optional
Remove only the dark-mode cover.
Returns

{ id, variant, cleared }. cleared is false when there was nothing to remove.

Organise

create_folder

Creates a folder and gives the agent Read + write on it, so it can put notes there. You can revoke that in Settings like any other grant.

Use it when
The work needs a place of its own.
Try asking
Make a Research folder and save these notes in it.
Inputs
name string, required
The folder's name.
Returns

{ id, name } of the new folder.

delete_note

Moves a note to Journal's Trash, where you can restore it. It never deletes a note for good.

Use it when
A note is a duplicate or no longer wanted.
Try asking
Delete the duplicate Trip plan note.
Inputs
id string, required
The note's id.
Returns

{ id, state: "trashed" }.

Ask for a page, get a page

An agent can write live blocks straight into a note: a React chart or a Mermaid diagram that runs where you read it.

It makes small edits too, changing one passage with replace_in_note and leaving the rest of the note as it was.

  • Create a note called Standup in my Work folder with today's summary.
  • In my Trip plan note, change the flight time from 9:40 to 10:15.
  • Redesign my Trip plan note as a day-by-day itinerary.
  • Use ~/Pictures/lisbon.jpg as the cover of my Trip plan note.

Then publish what it built

Live blocks an agent writes keep running when you publish the note as a public page, for anyone with the link.
